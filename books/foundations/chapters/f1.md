# Set up your machine and refresh Python
> lead: Install Python 3.13 with `uv`, get one LLM key into `.env`, and know which of the course's refresher files covers what, so the later chapters never stall on tooling.
meta: Foundations | Classes 01 to 03 | 10 min read

## Why it matters

Most "my agent does not work" problems in the first week are setup problems: the wrong Python, a key in the wrong place, a notebook run from the wrong folder. Doing this once, properly, saves the whole course.

## One-time setup (from `PREREQUISITES.md`)

| Step | What the repo says |
| --- | --- |
| Python | 3.10 or newer; individual projects pin an exact version in `.python-version` (the course pins 3.13) |
| `uv` | The package and project manager used all course long; each code folder ships `pyproject.toml` and `uv.lock`, so `uv sync` rebuilds the exact environment |
| Windows | Use Git Bash or Windows Terminal, never plain CMD or PowerShell |
| Editor | VS Code, because the course leans on `.py` scripts, a real terminal and proper debugging, not only notebooks |
| LLM key | At least **one** provider key. Free: **Groq** and **OpenRouter** (its `openrouter/free` model name auto-routes to a free model so it never goes stale). Paid: OpenAI, Anthropic |
| `.env` | Copy `.env.example` to `.env`, paste a real key (for example `GROQ_API_KEY=...`), then `uv run main.py`. `.env` is git-ignored at the repo root, so a real key cannot be committed by accident |

The free model in the LangChain notebook is created with `init_chat_model("openrouter/free", model_provider="openrouter")` (the notebook also names one specific free model, `nvidia/nemotron-3-super-120b-a12b:free`).

:::trap A real key is hard-coded in a notebook
`Langchain (1).ipynb` (Weekend 04, Models) sets an OpenRouter key directly in a cell, and the shared 12 July Colab sets a Groq key in a cell. I am not reproducing either. Treat any key that has been committed or shared as compromised: revoke it and use `.env` or Colab Secrets. (Chapter 18 notes a similar case.)
:::

## From the class 1 and 2 write-ups

*Read in full: `01 - 27 June - Python Setup & API Basics.md` and `02 - 28 June - Python Refresher.md`.*

**Class 1: environment and first API call.**

- **Ground rules.** Class starts at 8:00 AM IST, with a short grace only in class 1 and a five-minute wait after. Confirm video, audio and screen. Take notes and watch live rather than coding along, then practise from the recording: for every hour of class, about two hours of your own practice.
- **Shell.** Avoid CMD and PowerShell for this course: many Linux-style commands fail there, nearly every cloud machine you will SSH into is Linux, and the aim is to be platform-agnostic. On Windows use Git Bash or Windows Terminal. WSL works but was described as heavy.
- **`uv`** replaces the juggling of `pip`, `venv` and conda or poetry with one tool. The "room" analogy: `uv venv` builds a room, activating it walks you in, and what you install stays inside. `uv init` creates a project with a `pyproject.toml` (Python version and dependencies), like a recipe with exact quantities; it is the same idea as `package.json` or Maven. `uv` reads only `pyproject.toml`, so avoid mixing `pip install` and `uv add` in one project, and you can run through `uv run` without activating.
- **Why VS Code, not notebooks.** This is an agentic AI course, not classic data science: it leans on `.py` scripts, a built-in terminal (you will SSH into remote machines) and easier debugging.
- **Python highlights.** No type declarations, f-strings, and docstrings that matter more here because agent tooling reads them later. `if __name__ == "__main__":` was left as homework.
- **First API call.** The demo used `requests.get(url, params=params, timeout=10)` against a live currency-rate API (the timeout is "hanging up if no one answers in 10 seconds") and checked the USD to INR rate against a web search. If your code needs outside data, it needs an API, which is how LLMs are called too.
- **Framework philosophy.** "Agent is a concept; never learn a concept through a framework first." Plain Python before LangChain.

**Class 2: Python refresher.**

- **Windows fix-up.** Use Git Bash inside VS Code's terminal, not PowerShell. When an activation command differs by OS, ask an assistant to translate it instead of memorising variants.
- **Refresher.** Types, f-strings, `if/else`, lists, and indexing: positive from 0 and negative from -1 (in `["Tokyo", "Delhi", "London"]`, index -1 is London).
- **Classes.** A `BankAccount` with `__init__`, `deposit`, `withdraw` and a history list. Refusing a withdrawal larger than the balance is a first guardrail check.
- **`@dataclass`.** Removes boilerplate by generating `__init__` from the fields; use `field(default_factory=list)` for mutable defaults. It does not validate types.
- **Decorators.** A decorator wraps a function without changing it, like gift-wrap. `@decorator` is shorthand for `func = decorator(func)`. Use `functools.wraps` so the original name survives. The same pattern underlies the `@tool` decorator later.
- **Why Pydantic.** Python allows `create_user(25, "Mayank")` with the arguments swapped, and manual `isinstance` checks do not scale. A `BaseModel` converts `"25"` to `25` and raises `ValidationError` for a list. The book on Pydantic follows this one.
- **Q&A worth keeping.** The instructor said he personally avoids agent frameworks in his own production work when he can, preferring simple API orchestration to control token cost and execution; frameworks are like WhatsApp compared with SMS, convenient but worth understanding underneath. Agents for DevOps are framed as "mini interns". Vibe coding can get an app 80 to 90 percent of the way, but have a developer review security and data handling before publishing.

:::repo A cross-OS path audit in the course repo
`.github/workflows/path-audit.yml` runs `scripts/check_repo_paths.py` on Ubuntu, Windows and macOS for every push and pull request. The checkout itself is the real test, and the script then checks tracked paths for illegal Windows characters, reserved device names, leading or trailing spaces and dots, non-ASCII names, case-only and Unicode collisions, symlinks, submodules, paths over 200 characters (a warning at 180, because Windows allows 260 for the whole path including the student's clone folder), files over 50 MB, committed junk such as `.DS_Store` or `.venv`, and nested `.git` folders (which make `git add` skip a folder). It is a small, good example of a CI check that protects students, and a useful idea for your own repo.
:::

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Running with a different Python than the project pins | Import or syntax errors that only you see | Use `uv sync` and `uv run`, so the pinned version in `.python-version` is used |
| Real key pasted into a notebook cell | Key ends up in git or a shared Colab | Keep it in `.env` or Colab Secrets; revoke any key that was exposed |
| Using plain CMD or PowerShell on Windows | Shell commands in the notes fail | Use Git Bash or Windows Terminal |
