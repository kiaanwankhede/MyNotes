# Validating what an LLM gives you back
> lead: LLM text output is unreliable. Ask the provider to guarantee a Pydantic schema, constrain values with Literal, and retry with the validation error when it still fails.
meta: Pydantic | Part 8 | 15 min read

## Why it matters

An LLM asked for JSON may add a code fence, a friendly preamble, or return a number as a string. Cleaning that up with string tricks is fragile. The fix is to have the provider guarantee the shape and to validate what arrives.

## Core ideas

### Why raw text is a liability

Four realistic replies to the same prompt: clean JSON, JSON in a markdown fence, JSON after "Sure! Here it is:", and the right shape with wrong types (`"1999 dollars"`). Only the first survives `json.loads()` plus `model_validate()` untouched.

:::analogy Shouting an order versus a printed slip
A shouted order gets misheard. A printed checkbox slip is a response guaranteed to match a schema you defined.
:::

### Provider structured outputs

| Provider | Call | Result |
| --- | --- | --- |
| OpenAI | `client.responses.parse(model=..., input=..., text_format=Model)` | `response.output_parsed` |
| Anthropic | `client.messages.parse(model=..., max_tokens=..., messages=..., output_format=Model)` | `response.parsed_output` |

The same model works for both; only the SDK call changes. Add `ConfigDict(extra="forbid")` to a model you hand to a provider so the generated schema forbids surprise keys. The lower-level route is `Model.model_json_schema()` as a tool's `input_schema` with a forced `tool_choice`.

### Literal and the retry pattern

`Literal` physically limits a classification to allowed values. When validation still fails, the `ValidationError` text is the trigger for a retry: feed it into the next prompt and ask again, up to a limit.

```python
def classify_with_retry(text, max_retries=3):
    last_error = None
    for _ in range(max_retries):
        raw = ask_llm(text, previous_error=last_error)    # your LLM call
        try:
            return TicketClassification.model_validate_json(raw)
        except ValidationError as e:
            last_error = str(e)
    raise RuntimeError("Failed after max retries")
```

:::key Shape, not correctness
Structured output guarantees the **shape**. A well-formed answer can still be confidently wrong. Validation catches malformed data, not hallucinated facts.
:::

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Cleaning fences with string code | Breaks when the format shifts | Use provider structured output |
| Treating a valid object as true | Wrong facts accepted | Verify facts separately |
| No retry limit | Endless loop and cost | Cap the retries |

## Interview corner

:::qa How do you get reliable JSON from an LLM?
Pass a Pydantic model to the provider's structured-output call, constrain values with `Literal`, validate the result, and retry with the error fed back if it fails.
:::

:::qa Does validation make an answer correct?
No. It confirms the shape and constraints only. A confidently wrong value in the right shape still passes.
:::
