## Why it matters

`os.getenv()` always returns a string or `None`. `DEBUG="false"` is a non-empty string, so `if debug:` is true. Every project ends up rewriting the same parsing code.

## Core ideas

`BaseSettings` (from the separate `pydantic-settings` package) extends `BaseModel`. Fields not passed as keyword arguments are filled from the environment, and keyword arguments are handy for overrides in tests.

```python
from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict

class AppSettings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")
    api_key: SecretStr
    max_connections: int = Field(default=100, ge=1, le=1000)
    debug: bool = False
```

| Feature | How it works |
| --- | --- |
| Name mapping | The variable name matches the field name, case-insensitive (`api_key` reads `API_KEY`). `alias`, `validation_alias`, `AliasChoices` or `env_prefix` change it |
| `.env` files | `env_file`, or a tuple of files where later ones win. Real environment variables beat the file |
| Unknown entries | With the default `extra='forbid'`, unknown `.env` entries raise an error; `extra="ignore"` skips them |
| Nested values | With `env_nested_delimiter="__"`, `DB__HOST` fills `db.host`. Lists and dicts are read as JSON |
| Secrets directory | `secrets_dir`: each file's name is the key, its contents the value. Lower priority than the environment and `.env` |
| Priority | Environment over `.env` over secrets directory; `settings_customise_sources` reorders |
| Defaults | **Validated**, unlike in `BaseModel` (set `validate_default=False` to skip) |
| Command line | `cli_parse_args=True` parses `sys.argv` into fields |

`settings.max_connections` is a real `int`, `debug` a real `bool`, and `api_key` prints masked; read it on purpose with `.get_secret_value()`.

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| `if os.getenv("DEBUG")` | `"false"` is truthy | A `bool` field in `BaseSettings` |
| Keys as plain `str` | Secret printed in logs | `SecretStr` |
| Unknown entry in `.env` | `ValidationError` on start | `extra="ignore"` |

## Interview corner

:::qa Why BaseSettings over os.getenv?
It gives typed, validated configuration with defaults and constraints, reads `.env`, and masks secrets, instead of hand-written string parsing.
:::

:::qa Which wins: an environment variable or the .env file?
The real environment variable. A tuple of `.env` files loads in order, with later files overriding earlier ones.
:::
