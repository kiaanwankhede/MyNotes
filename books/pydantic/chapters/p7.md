# Strict mode and JSON Schema
> lead: Turn coercion off when silent conversion would hide bugs, and turn a model into a JSON Schema, the document that tells an API or an LLM what shape to expect.
meta: Pydantic | Docs "Strict mode" and "JSON Schema" | 12 min read

## Why it matters

Lax mode is friendly, but it can hide mistakes. The schema is how a model becomes machine-readable, and chapter 11 uses it to ask an LLM for a specific shape.

## Core ideas

### Strict mode

Strict mode refuses to convert: `"123"` is no longer an `int`. Four ways to turn it on:

| Where | How |
| --- | --- |
| One call | `Model.model_validate(data, strict=True)` |
| One field | `Field(strict=True)` or `Annotated[int, Field(strict=True)]` |
| A type | `StrictInt`, `StrictStr`, `StrictBool`, or `Annotated[UUID, Strict()]` |
| The whole model | `model_config = ConfigDict(strict=True)`; a field can opt out with `Field(strict=False)` |

Python mode and JSON mode differ: with strict on, a date string is rejected from Python input but accepted from JSON, since JSON has no date type. When adding strict mode to a running app, watch for callers who relied on coercion.

### JSON Schema

`Model.model_json_schema()` returns a dict (not a string) describing the model, using JSON Schema 2020-12 and OpenAPI 3.1. `TypeAdapter(list[int]).json_schema()` does it for any type.

```python
class Ticket(BaseModel):
    priority: Literal["low", "medium", "high"]
    summary: str = Field(max_length=200, description="One-line summary")

Ticket.model_json_schema()
```

- Constraints map to standard keywords: `max_length` becomes `maxLength`, `gt` becomes `exclusiveMinimum`, `PositiveInt` becomes `exclusiveMinimum: 0`, `EmailStr` becomes `format: email`, and `SecretStr` adds `writeOnly`.
- `title`, `description`, `examples` and `json_schema_extra` on a field show up in the schema. The `description` is what a model reads, so write it as an instruction.
- Nested models go under `$defs` and are referenced with `$ref`.
- `mode="validation"` (default) describes accepted input; `mode="serialization"` describes output. A `Decimal` accepts a number or string as input but is emitted as a string.
- An `Enum` becomes an `enum` list. (The docs say little about `Literal`; check the output of your own models.)

:::key Why chapter 11 cares
The dict from `model_json_schema()` is exactly what you hand a provider as a tool's input schema. Add `extra="forbid"` so the schema forbids unknown keys.
:::

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Turning on strict mode without checking callers | Clients that sent `"5"` now fail | Roll out gradually and watch failures |
| Treating the schema as a string | Type errors | It is a dict; `json.dumps` it when needed |

## Interview corner

:::qa How do you turn off coercion?
Strict mode: per call (`strict=True`), per field, with a `Strict*` type, or for the whole model through `ConfigDict(strict=True)`.
:::

:::qa What does model_json_schema give you?
A dict describing the model's fields, types and constraints in JSON Schema, which APIs use for documentation and LLM providers use to constrain output.
:::
