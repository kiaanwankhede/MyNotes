# Nested models
> lead: Use one model as another's field type and validation cascades through every layer, with errors that name the exact path.
meta: Pydantic | Docs "Models", class 03, the notebook | 10 min read

## Why it matters

Real data, including JSON from an API or an LLM, is nested: an applicant has an address, an order has a list of items. The class pointed out that nested models mirror nested JSON, which is the shape of most API payloads and LLM structured outputs.

## Core ideas

```python
from pydantic import BaseModel, Field

class Address(BaseModel):
    city: str
    state: str
    pin_code: str

class Applicant(BaseModel):
    name: str
    email: str
    address: Address
    history: list[str] = []

a = Applicant.model_validate(
    {"name": "R", "email": "r@x.com",
     "address": {"city": "Pune", "state": "MH", "pin_code": "411001"}})
a.address.city          # dot-chain access, fully typed
```

- Validating the outer model builds the inner models from the inner dicts. `model_dump()` converts everything back, recursively.
- A bad inner value gives an error whose location is the full path, such as `address.pin_code`.
- A whole nested object can be optional with `Address | None = None`. Lists of models work the same way. There is no practical depth limit.
- The notebook's version of this puts a `Field(gt=1000, lt=43125315)` constraint on `pin_code`, to show that nested models carry their own rules.

:::analogy The org chart
A company contains departments, which contain employees. Validate the company and every layer beneath is validated for you. (Instructor's site.)
:::

### Inheritance is also allowed

From the class Q&A: a model can extend another (`class Applicant(Address)` inherits its fields and validators) with ordinary Python inheritance. Prefer composition (a field of type `Address`) when the data really is "has an", and inheritance only when it is "is a".

### Self-referencing data and forward references

Data that refers to itself (a parent that points back to a child) is detected and reported as a `ValidationError` instead of recursing forever. A model that mentions a class defined later uses a string annotation, and you call `model_rebuild()` once the names exist.

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Expecting int to str coercion in a nested field | A nested `12345` is rejected for a `str` field | Convert it yourself |
| Calling `dict()` and expecting nested dicts | Inner models stay as models | Use `model_dump()` |
