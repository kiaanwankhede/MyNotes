# Your first model
> lead: A BaseModel is a class that inspects its data: it validates types, converts safe values, and raises one clear error listing every problem.
meta: Pydantic | Part 2 | 10 min read

## Why it matters

A plain class and a dataclass look just like a model but check nothing. Only `BaseModel` refuses bad data before the object exists.

## Core ideas

| Option | Accepts arguments | Validates |
| --- | --- | --- |
| Plain class with hints only | No (no `__init__`) | No |
| `@dataclass` | Yes | No: `age="not a number"` is accepted |
| `BaseModel` | Yes | Yes |

:::analogy The customs form
A plain class is a form nobody hands out, a dataclass is a form nobody reads, and a `BaseModel` is a form with an officer behind it.
:::

```python
from pydantic import BaseModel, ValidationError

class Signup(BaseModel):
    username: str
    age: int
    newsletter: bool = False        # has a default, so optional

Signup(username="a", age="30")      # age becomes the int 30
try:
    Signup(username="a")            # missing age
except ValidationError as e:
    print(e)                        # names every problem field
```

### Coercion: lax mode by default

Pydantic converts safe values (`"30"` to `30`) and refuses ambiguous ones. Strict mode (`ConfigDict(strict=True)`) turns conversion off.

:::trap Coercion is not symmetric
`"25"` becomes `25` for an `int` field, but `12345` is **not** turned into `"12345"` for a `str` field. It is rejected.
:::

### Creating and dumping

`Model(**data)` and `Model.model_validate(data)` validate the same way; use `model_validate` when you need options such as `strict=True`. `model_dump()` returns a dict (database, other functions); `model_dump_json(indent=2)` returns a JSON string. Fields without a default are required, and the error lists all missing fields at once, which is what later powers the retry-with-error pattern.

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Using a dataclass for external data | Bad types pass silently | Use `BaseModel` |
| Expecting int to str coercion | Unexpected `ValidationError` | Convert yourself or annotate with the right type |

## Interview corner

:::qa BaseModel versus dataclass?
Both give a clean constructor from hints. Only `BaseModel` validates and coerces, and it raises `ValidationError` before the object is created.
:::

:::qa What is lax mode?
Pydantic's default: it converts clearly compatible values (a numeric string to an int) and rejects the rest. Strict mode disables conversion.
:::
