# Why validation exists, and type hints
> lead: Python will happily run with garbage data. Type hints describe what you expect, but only a library like Pydantic enforces it.
meta: Pydantic | Part 1 | 8 min read

## Why it matters

Data from outside your code (an API, a form, a file, an LLM) can be anything. If nothing checks it at the entrance, the crash happens deep inside, far from the real cause.

## Core ideas

### The dynamic typing problem

A function that computes `2026 - age` works for `28` and crashes for `"unknown"`, with an error that points at the subtraction, not at the bad input. The bug is that nothing inspected the data when it arrived.

:::analogy The courier with no intake desk
A courier that loads any parcel, whatever the label, finds the problem three stops into the route. Pydantic is the intake desk that refuses the bad parcel at the door.
:::

### Type hints are documentation, not enforcement

`age: int = "not a number"` runs without complaint. Hints are read by humans, IDEs and Pydantic, and by nothing else at runtime.

```python
tags: list[str] = ["python", "pydantic"]        # lowercase built-ins since Python 3.9
word_counts: dict[str, int] = {"error": 12}

def format_price(amount: float, currency: str = "USD") -> str:
    return f"{currency} {amount:.2f}"
```

### Optional and Literal

`str | None` (or `Optional[str]`) means the value may be absent. `Literal["low", "medium", "high"]` limits a value to a fixed set. Alone they are only documentation; once Pydantic enforces them, `Literal` is how you stop a model returning "kinda urgent i guess".

```python
from typing import Literal
priority: Literal["low", "medium", "high"] = "medium"
phone: str | None = None
```

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Believing a hint is a check | Wrong types flow through silently | Validate at the boundary with a `BaseModel` |
| Using `List`/`Dict` from `typing` in new code | Works but dated | Use `list[str]`, `dict[str, int]` |

## Interview corner

:::qa Does Python enforce type hints?
No. At runtime they are ignored. They help readers, IDEs and libraries such as Pydantic, which reads them and enforces them.
:::

:::qa Why is validating at the boundary better than inside the function?
The error appears where the bad data entered, with a clear message, instead of as an unrelated crash several calls later.
:::
