## Why it matters

This is where Pydantic is "everywhere": an endpoint that takes a model is validated before your function body runs.

## Core ideas

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr, Field

app = FastAPI()

class Applicant(BaseModel):
    full_name: str = Field(min_length=2, max_length=100)
    email: EmailStr

class Receipt(BaseModel):
    full_name: str

@app.post("/apply", response_model=Receipt)
def apply(a: Applicant) -> Receipt:
    return Receipt(full_name=a.full_name)
```

- **Request validation.** Malformed bodies are rejected with a detailed error before the function runs; no manual `if` checks.
- **`response_model=`** filters what you return down to that shape, a safety net against leaking extra fields.
- **Docs.** The model's JSON Schema feeds the `/docs` page, so every `Field()` constraint becomes a documented API constraint.

:::analogy One scanner at the terminal entrance
Instead of each gate building its own detector, the terminal has one scanner everyone passes. Your model is that scanner. (Instructor's site.)

### From the FastAPI documentation

:::note Sources
FastAPI tutorial pages: [Request Body](https://fastapi.tiangolo.com/tutorial/body/), [Response Model](https://fastapi.tiangolo.com/tutorial/response-model/), [Extra Models](https://fastapi.tiangolo.com/tutorial/extra-models/), [Body - Updates](https://fastapi.tiangolo.com/tutorial/body-updates/) and [Query Parameter Models](https://fastapi.tiangolo.com/tutorial/query-param-models/), all read in full on 31 Oct 2026. Other FastAPI pages were not read.
:::

- **Request body.** Declare a parameter whose type is a Pydantic model and FastAPI reads the JSON body, converts, validates (a bad body gives a clear error naming the place), gives you a model instance and adds the schema to the docs. Resolution rule: a name in the path is a path parameter, a simple type is a query parameter, a Pydantic model is the body. A field is optional because of its **default**, not because of `| None`. Bodies on `GET` are discouraged.
- **Response model.** A return annotation (`-> Item`) or `response_model=` validates the output (invalid output is a server error, because your code is wrong), adds a JSON Schema, serializes with Pydantic, and **filters** the output to the declared fields. If both are given, `response_model` wins; `response_model=None` turns it off.
- **Two models, one for input and one for output** keeps secrets out: `UserIn` has `password`, `UserOut` does not. A parent/child pair (`BaseUser` returned, `UserIn` actually returned) keeps editor support and still filters.
- **Encoding switches:** `response_model_exclude_unset`, `_exclude_defaults`, `_exclude_none`, `_include`, `_exclude`. Fields explicitly set to a default value are still kept by `exclude_unset`.
- **Extra models:** share fields through a base class (`UserBase`, `UserIn`, `UserOut`, `UserInDB`). Never store plaintext passwords. A union response (`anyOf` in OpenAPI) should list the most specific type first. The page also has a note about writing the union as a value on Python 3.10, which I could not confirm from the text I got, so check it before relying on it.
- **Updates.** `PUT` replaces, so omitted fields fall back to defaults and overwrite stored values. For `PATCH`, use `model_dump(exclude_unset=True)` and `model_copy(update=...)`.
- **Query parameter models** (FastAPI 0.115.0 and later): group query parameters in a model with `Query()`; `extra='forbid'` rejects unknown parameters with an `extra_forbidden` error; several models can be combined, and `Model | None = None` makes a group optional.

## See it at project scale

The Meridian capstone (Agentic AI with LangChain, last chapter, "Module 6") shows this pattern in a real service: four small request and reply classes in `schemas.py`, seven thin routes, error handlers that turn your own exceptions into 503 and 422 replies, and the `/docs` page generated from the same code.

## Common mistakes

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Returning an internal model directly | Password or internal ids leak | Declare `response_model` |

## Interview corner

:::qa What does response_model do?
It validates and filters the returned object to the declared shape, so extra fields cannot leak, and it documents the response in `/docs`.
:::
