# Joule Studio tutorial 27: getting productive with Joule Work

*The final tutorial in this series, and the only one that never touches Joule Studio at all — a pure walkthrough of Joule Work's own features: Conversations, Cards, Spaces, and agent routing, on the Business AI Platform trial.*

## 1. The scenario

A Demand and Supply Planner at a discrete manufacturing company needs to review production actuals against the IBP (Integrated Business Planning) forecast for the coming quarter, identify potential supply gaps, and decide where to act — without switching between SAP S/4HANA, SAP IBP, and manual reports. The data used is sample data provided as part of the BAIP trial environment, for a fictional business.

BAIP itself is described directly: *"a unified enterprise AI foundation"* combining data, process context, and governance. Joule Work is described as *"a central workspace where AI agents handle busywork"* — and later, more specifically, as *"a persistent, context-aware workspace rather than a stateless chatbot"* and *"an orchestration layer for AI agents built on BAIP."*

## 2. Step 1 — Present actuals and forecast data

In Joule Work Desktop, starting a new conversation, the prompt is:

```console
Show me production actuals vs IBP forecast for Q3
```

Joule retrieves actuals from SAP S/4HANA and the forecast from SAP IBP, returning them as a structured result — a visual **Card** with key metrics highlighted. The forecast itself is generated by **SAP RPT 1.5**, named directly as "SAP's tabular AI model," trained on historical production data.

## 3. Step 2 — Create and learn about Spaces

Still in the same conversation, the actuals-vs-forecast card is saved to a new **Space** — for example, "Q3 Production Review." Opening the Space shows the pinned card. A follow-up question (for example, which region or product line has the largest variance) is asked, and that result is added to the same Space as a second card.

Spaces are described directly as *"dynamically generated dashboards that automatically assemble relevant insights and data around a specific business goal or task in real time"* — *"the connective tissue between conversations and ongoing work,"* letting you *"build up a curated view of a topic over time."* They persist between sessions: returning to a Space later shows its cards exactly as they were left.

## 4. Step 3 — Call an agent in the Space's context

With the Space open, a new conversation starts with the Space active, and the prompt addresses an agent directly:

```console
@planning-agent Analyze the Q3 variance data and suggest where we should rebalance production.
```

> [!NOTE]
> The tutorial's own text has a small inconsistency here worth knowing about rather than smoothing over: it says to "call the planning agent," but the very next sentence describes Joule routing the request to "the manufacturing agent." The tutorial doesn't explain the discrepancy between the two names. This book reports it as written rather than guessing which name is correct.

Joule routes the request to an agent, which returns a prioritized set of production adjustment recommendations with projected impact. That output is added to the Space as a new card.

## 5. Step 4 — A genuine data-gap guardrail

Back in the original conversation (not the Space), the prompt is:

```console
What are the current live production rates on Line 4?
```

Joule reports a **data gap**: live production rate data isn't available in the connected sources. It does not estimate or fabricate an answer — it states what's missing and why it can't fully respond.

> [!CAUTION]
> **🔒 "Say what's missing" rather than guess**
> This is the same grounding principle named explicitly in [Tutorial 11's](joule-studio-tutorial-11-demand-spike-agent.md) guardrail list ("if any API call fails during data retrieval, the agent must report which data is missing") and in [Tutorial 26's](joule-studio-tutorial-26-supplier-risk-monitor-agent.md) agent response ("I'll never make up information"), demonstrated here directly in the end-user Joule Work experience rather than inside a generated agent's own system prompt. It's a pattern that shows up at every layer of this book's material, from hand-built agent guardrails down to the base assistant's own behavior.

> [!TIP]
> **🧩 Design question**
> *"A planner asks why they'd use a Space instead of just asking Joule the same questions over and over in a fresh conversation each time."* Talk about: a Space's persistence and automatic assembly — cards pinned to a Space stay there across sessions and can be built up over time into a curated view of a specific goal (here, "Q3 Production Review"), whereas a fresh conversation has no memory of prior results and nothing to return to later; the Space is explicitly framed as "connective tissue" precisely because it's meant to outlive any single conversation.

## Recap

- This tutorial is a pure Joule Work walkthrough — no Joule Studio build, no generated code, no screenshots
- 3 core concepts carry the scenario: Conversations (with follow-up context), Cards (saved result visuals), and Spaces (persistent, goal-oriented dashboards)
- An `@agent-name` syntax routes a request to a specific agent from within a Space's context
- Asked for data it doesn't have (live Line 4 production rates), Joule reports the gap explicitly rather than fabricating an answer — the same grounding principle seen throughout this book's generated-agent guardrails, demonstrated here in the base assistant itself
